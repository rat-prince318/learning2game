# 团队交接与第一批任务

A 模块已提供独立运行入口、契约、样例和测试。团队先围绕共享数据接通一条流程，再替换各自的样例。

## 给 B

1. 对照 `examples/knowledge/computing.json` 输出 `KnowledgeBundle`，保留来源 evidence 和 locator。
2. 分开标记 reliable、uncertain、conflict；有歧义或模糊图像的知识不能默认可靠。
3. 第一批提供一份文字材料和一份必须理解图中连接关系的图像材料。提供人工参考配对及来源。
4. 可直接把 bundle 交给 D；若需 A 编排，按 `docs/CONTRACTS.md` 实现三个 MaterialTools 方法。

## 给 D

1. 维护正式共享模型；当前可直接导入 `matching_agent.models`。字段修改同时更新 Schema 和样例。
2. 在 FastAPI 中调用 A 的三个 async 入口，将 `on_event` 接入任务状态。
3. 保存方案快照和真实用户确认；用户改参数后重新规划。不要把确认按钮变成模型工具。
4. 仅在 `GenerationResult.game` 非空且验证通过时保存为可玩游戏。
5. 从内部配置生成独立、不泄露答案的公开卡片；正确对应关系保留在服务端。
6. 实现判分、重复事件去重、统计与薄弱点判定，将每轮所有知识的表现交给 A。
7. 将原偏好继续传入 `generate_feedback`；下一轮把反馈参数交给 `prepare_plan`，确认后传入上一轮 game。
8. 实现上传、存储、身份绑定、任务取消/重启处理和数据清理。A 的例外码可映射为 D 的统一错误响应。

## 给 C

1. 先与 D 约定公开游戏格式；`examples/games/` 中的文件是含答案的内部配置，不能直接发送浏览器。
2. 展示 plan 的实际题量、知识点、理由和警告，支持修改并确认。
3. 展示任务阶段和失败原因；修复中保持生成状态，不提前开放游戏。
4. 游戏结束后，数字从 feedback.statistics 读取；文字建议来自 summary/reviews。
5. “再练薄弱点”先展示新方案，确认后生成；展示无法安全改写时的提示。

## A 的报告材料

可引用 Agent 工作流、工具列表、参数与结果示例、个性化差异、重复定义修复和无法修复的失败记录。离线记录在 `evidence/offline/`；真实记录以 `runs/live_*` manifest 为准，不能混在同一个真实模型成功率分母中。

内容准确率需要 A/B 对实际生成配对人工复核。界面可玩性、端到端生成成功率和学习统计正确性分别由 C/D 联调验证。当前工具调用测试不代表全系统已完成多模态、网页或真实学习效果验收。

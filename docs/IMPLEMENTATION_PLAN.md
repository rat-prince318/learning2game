# 成员 C 实现计划

目标：完成创建、配对、报告和薄弱点再练习的前端闭环，交付可运行代码、接口交接资料及 C7 检查结果。

技术栈：原生 HTML/CSS/JavaScript ES Modules；Node.js 22+ 提供静态资源、可替换的 API 代理和独立演示服务。浏览器不下载内部答案配置。全部代码位于 learning2game。

## 架构与视觉

- 页面层：创建、游戏、报告三个 hash 路由，静态 HTML 保持表单和键盘焦点稳定。
- 引擎层：MatchingEngine 单独拥有选择、提交锁、未确认事件及会话版本；页面只渲染。
- 数据层：ApiClient 统一处理真实 HTTP、超时、错误码和任务轮询；真实 /api 与演示 /demo-api 明确隔离，失败不自动切回演示。
- 演示服务：服务端保留答案，提供固定的细胞结构教学样例，明确说明未运行资料提取和 LLM 工具调用。上传的本地文件只用于前端预览。
- 刷新恢复：本地仅保存材料、任务、游戏、会话引用和未确认事件；会话统计通过 GET /sessions/{id} 恢复，以服务端为准。
- 视觉：冷灰纸面 #F4F7FC、深蓝墨色 #203256、青绿 #087F8C、浅青 #DDF3F1、橙色反馈 #B9681E；中文正文用系统无衬线字体，英文标题用 Georgia，统计用等宽数字。签名元素为概念与释义之间的配对连接符。
- 键盘：原生 button 支持 Tab/Enter/Space，卡片支持方向键/Home/End，反馈使用 aria-live，状态同时提供文字与符号。

## 验证方法

1. Node 内置测试覆盖引擎并发、随机顺序、事件幂等、过期结果、API 错误和任务终态。
2. HTTP 集成覆盖演示服务和真实代理模式的完整请求链，内部答案只在服务端测试上下文中用于构造结果。
3. 浏览器检查实际页面、完整用户路径、手机布局和键盘输入；保存截图与结果记录。
4. 不能将演示服务通过等同于 A/B 的多模态理解或 D 的 FastAPI/SQLite 真实集成通过。
